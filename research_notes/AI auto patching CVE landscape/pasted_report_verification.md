## Q1 — ARTEX (claims 1–3)

### Takeaway
The core ARTEX story checks out. Autumn-27, who also wrote ScopeSentry, published it July 26 2026 under AGPL-3.0, and it went non-public around Oct 7–8 2026. Forks including lenaxia/artex and ScopeWeaver survive. Backdoored Docker images were removed around Nov 5, and the FBI issued a FLASH on Nov 13. Several details in the pasted report are wrong or loose. The agents are planner/worker/mainagent, not "conductor/worker/report". The 12k-fork figure rests on one secondary source. The 1,645 console count is BadByte's own and is not via THN. The Korean bank campaign used several models, with DeepSeek as primary.

### Cited Findings
- The ARTEX architecture is a Go monolith with an embedded Next.js UI and PostgreSQL. Its agent roles are goals/planner/worker/mainagent, built on Autumn-27's `norma` SDK — [BaaRai/ARTEX README](https://raw.githubusercontent.com/BaaRai/ARTEX/HEAD/README.md); [Core-RCE/ARTEX-original-version README](https://raw.githubusercontent.com/Core-RCE/ARTEX-original-version/HEAD/README.md)
- The last upstream commit was e6ec569 / v0.3.15 on 2026-10-07. jaykwok says the original repo was deleted, while BaaRai says it is "no longer public" — [jaykwok/ARTEX README](https://raw.githubusercontent.com/jaykwok/ARTEX/HEAD/README.md); [BaaRai/ARTEX README](https://raw.githubusercontent.com/BaaRai/ARTEX/HEAD/README.md)
- The original Docker image `autumn27/artex` has also been pulled ("已下架", "taken down"), and forks now build from source — [jaykwok/ARTEX README](https://raw.githubusercontent.com/jaykwok/ARTEX/HEAD/README.md)
- Largest live re-hosts (GitHub search, 2026-11-19): BaaRai/ARTEX 9.8k stars / 4.1k forks; jiwoochris/artex-global 4.0k / 3.4k; RuoJi6/ARTEX 2.3k / 1.4k; Hinln/ARTEX 1.7k / 2.2k; cskwork/scopeweaver 1.1k / 848; failsafe-security/artex 874 / 285.
- tomicdd/artex and congdonglinux/artex were backdoored. Docker removed both on Nov 5. congdonglinux was registered Oct 20 — [Kodem](https://www.kodemsecurity.com/resources/artex-ai-pentest-framework-backdoored-docker-image-iocs-response-runbook); [vulnpocalypse](https://vulnpocalypse.dev/advisories/artex-docker-image-backdoored-researcher-says-cert-in-flags-crafty-falcon/)
- FBI FLASH, Nov 13 2026: >1,600 exposed consoles, privileged access in under 3 hours in some cases, and forks plus ARTEX PRO still circulating — [Industrial Cyber](https://industrialcyber.co/industrial-cyber-attacks/fbi-warns-hackers-weaponizing-artex-ai-framework-to-automate-attacks-on-energy-manufacturing-telecom/); [Hackread](https://hackread.com/fbi-artex-ai-tool-hackers-gain-privileged-access/)
- Qualys, Nov 15 2026: under 3 hours to privileged access vs a median of 7 days to fix criticals (down from 9) — [Qualys blog](https://blog.qualys.com/misc/2026/11/15/artex-moves-at-machine-speed-what-risk-owners-need-to-change)

### Inferences
- The upstream was most likely deleted or made private on Oct 8. Since it cannot be queried, the ">12,000 forks" figure cannot be checked against GitHub. It is plausible given the fork counts of the re-hosts.
- The FBI warning concerns attacker use of ARTEX. It does not concern the Docker backdoor, and the pasted report runs the two together.

### Gaps
- I could not fetch BadByte, BleepingComputer or the FBI FLASH directly (hosts blocked), so the figures come from search summaries.
- I found no Talos or ThreatDefence ARTEX publication.
- I could not find THN's own article.

## Q2 — Anthropic / Claude (claims 4–5)

### Takeaway
The ban on subscription OAuth outside Anthropic's own apps is real and current. The pasted report's description of `claude -p` / Agent SDK billing is out of date: the separate-credit plan was paused on June 15 2026, and signed-in usage still draws from plan limits. The new monthly API credits (Oct 7 2026) apply only when you use an API key. The Claude Security plugin and the Oct 2026 continuous-scanning update are real. The update is dated Oct 21 by most outlets and is limited to Enterprise. The GitHub Action stats are accurate.

### Cited Findings
- OAuth is for "ordinary use of Claude Code and other native Anthropic applications". Developers building products should use API keys and may not route requests through plan credentials for their users — [code.claude.com](https://code.claude.com/docs/en/legal-and-compliance)
- Help Center updates: June 15 2026 (change paused) and Oct 7 2026 (monthly API credits via an API key) — [support.claude.com](https://support.claude.com/en/articles/15036540-use-the-claude-agent-sdk-with-your-claude-plan)
- The plugin beta launched July 22 2026 — [MarkTechPost](https://www.marktechpost.com/2026/07/22/anthropic-releases-claude-security-plugin-for-claude-code-in-beta-a-multi-agent-vulnerability-scanner-that-runs-in-your-terminal/)
- The continuous-scanning update is in public beta for Enterprise — [Help Net Security](https://www.helpnetsecurity.com/2026/10/22/claude-security-continuous-scanning-update/)

### Inferences
- Hermes Agent offers Anthropic OAuth login with Claude Max. Under Anthropic's stated policy, using it that way appears non-compliant, while using an API key is fine. This is my reading of the two documents. Anthropic has not ruled on Hermes specifically.

### Gaps
- I did not find the v2.1.154 minimum in Anthropic's own docs. Only MarkTechPost states it.

## Q3 — Hermes, benchmark figures, other vendors (claims 6–8)

### Takeaway
The Hermes description is accurate: MIT license, ~265k stars, active today. The slopsquatting figures and the Codex Security CLI release are confirmed.
